You are a senior frontend engineer tasked with optimizing the Apex mobile experience. The app is a progressive web app (PWA) for exam preparation with the following structure:

## Key Issues to Address

### 1. Viewport Meta Tag - Accessibility Violation (Line 5 in index.html)
**Current:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, user-scalable=no, maximum-scale=1">
```
**Problem:** `user-scalable=no` and `maximum-scale=1` prevent users from zooming, violating WCAG 2.1 success criterion 1.4.4 (Resize Text) and 1.4.10 (Reflow). This is a serious accessibility issue.
**Fix:** Remove `user-scalable=no, maximum-scale=1` to allow zoom for users with low vision. Keep `viewport-fit=cover` for edge-to-edge display on notched devices.

### 2. Landing Page Viewport is Correct (landing.html line 5)
```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```
The landing page has the correct viewport setting. Consider aligning index.html with this pattern.

### 3. Media Queries Breakpoints
- Main app uses `@media (max-width: 860px)` - good for tablets in portrait
- Consider adding `@media (max-width: 480px)` for small phones to further optimize spacing
- Landing page uses multiple breakpoints: 900px, 700px, 600px - a more refined approach

### 4. Sidebar Navigation - Needs Mobile Treatment
The `#sidebar` element (lines 8082-8096 in index.html) is a fixed-width sidebar (260px) that pushes content on desktop. On mobile:
- Should collapse by default (overlay mode rather than push)
- Needs smooth transition animation
- The `#sb-toggle` button exists but needs mobile-specific behavior
- Consider hiding sidebar content on mobile and showing only when activated

### 5. Touch Targets - WCAG Compliance Needed
Many interactive elements may have insufficient touch targets:
- SVG icons are often 22x22px or 24x24px - needs 44x44px minimum for actives
- Buttons like `.icon-btn` at 34x34px (line 10 of apex-mobile-ux.css) are closer but may need padding
- Grade buttons `.grade-btn` have min-height: 32px (line 1753) - consider 44px minimum

### 6. Bottom Navigation - Hidden on Desktop
`<nav id="bottomnav">` (line 1639 of apex-mobile-ux.css) is `display:none` on desktop and should be the primary navigation on mobile. Needs:
- Visible on mobile by default
- Proper z-index for modals to overlay correctly
- Active state styling

### 7. Command Palette - Terminal-Style Modal
The `#cmd-palette` (lines 2069-2075 in index.html) is a full-screen terminal-style modal. On mobile:
- Should have proper viewport-safe padding
- Escape key should be replaced with visible close button
- Input should be the first focusable element

### 8. Keyboard Shortcuts - Desktop-Only UX
Many text references to keyboard shortcuts (⌘Z for undo, ⌘S) won't work on mobile:
- Undo button shows `title="Undo (⌘Z)"` - consider adding a visible hint for mobile
- Create alternative gestures or on-screen buttons

### 9. Form Elements - Mobile Input Optimization
- `select.inp` elements need adequate height for touch
- Date/time inputs should use mobile-friendly pickers
- Text inputs need sufficient padding

### 10. Safe Area Insets - Notch/Home Indicator Support
Lines 18, 1642 of apex-mobile-ux.css use `env(safe-area-inset-bottom)` - needs verification for:
- Top safe area (notch)
- Left/right for iPad with pencil
- Consistent application to all fixed-position elements

### 11. Performance Optimization for Mobile
- Starfield cosmos animation (lines 8700-8729 in JS) - def render on low-end devices
- Backdrop filters (blurs) are expensive on mobile - consider reducing or disabling
- Google Fonts - already preloading but consider `font-display: swap`

### 12. PWA Enhancements
manifest.json already has excellent mobile configuration. Consider:
- Adding `prefer_related_applications: true` with Play Store link
- Adding more shortcuts for quick actions (e.g., "Log Session", "Reviews")
- Consider `theme_color` dynamic updates

### 13. Color Scheme and Contrast
- Verify WCAG 2.1 AA contrast ratios (4.5:1) for text
- Consider adding `prefers-color-scheme: dark` support (already dark by default, but media query for consistency)
- Consider `prefers-reduced-motion` for animations

### 14. Touch Gestures
Consider adding touch gestures for common actions:
- Swipe to navigate between sections
- Pull to refresh
- Long press for context menu
